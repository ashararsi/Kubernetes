3. Prerequisites

  • Docker Desktop installed and running (whale icon in menu bar)
  • Kubernetes enabled: Docker Desktop → Settings → Kubernetes → Enable Kubernetes
  • kubectl — bundled with Docker Desktop

Open a terminal and cd "/Users/apple/Downloads/files (1)" before running any commands.

4. Docker Only (no Kubernetes)

Build the image:

bash 
docker build -t construction-node-app:1.0 .

Run a container:

bash 
docker run --rm -d --name construction-welcome -p 3000:3000 construction-node-app:1.0
URLResult
http://localhost:3000App home page
http://localhost:3000/healthReturns ok

Stop the container:

bash 
docker stop construction-welcome

5. Kubernetes — First-Time Setup

  1. Open Docker Desktop and enable Kubernetes. Wait until fully ready.
  2. Check context: 
    kubectl config get-contexts
    Active context (e.g. docker-desktop) should be marked CURRENT.
  3. Verify the cluster: 
    kubectl cluster-info
kubectl get nodes

6. Build Image and Deploy

bash 
cd "/Users/apple/Downloads/files (1)"
docker build -t construction-node-app:1.0 .
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml

Check status:

bash 
kubectl rollout status deployment/construction-app
kubectl get pods,svc -l app=construction-mgmt

You should see the pod READY 1/1 and Running.

7. Open the App in a Browser

Option A — Port Forward (Recommended)

bash 
kubectl port-forward svc/construction-app-svc 8080:80

Open http://localhost:8080. Press Ctrl+C to stop.

Option B — NodePort

Service maps NodePort 30080. On Docker Desktop, Option A is more reliable.

9. Scale Replicas

bash 
kubectl scale deployment construction-app --replicas=2
kubectl get pods -l app=construction-mgmt

To make it permanent, edit spec.replicas in deployment.yaml and re-apply.

10. Update After a New Image

  1. Build with a new tag: 
    docker build -t construction-node-app:1.1 .
  2. Update image: in deployment.yaml, then: 
    kubectl apply -f deployment.yaml
kubectl rollout status deployment/construction-app

Keeping the same tag? Just restart pods:

bash 
kubectl rollout restart deployment/construction-app

11. Cleanup

bash 
kubectl delete -f service.yaml --ignore-not-found
kubectl delete -f deployment.yaml --ignore-not-found

Docker-only container:

bash 
docker rm -f construction-welcome 2>/dev/null

12. What to Learn or Build Next

  1. Registry — Push to Docker Hub / GHCR; use full image name in Deployment.
  2. Secrets / ConfigMap — DB URLs, API keys; avoid hardcoding in the image.
  3. Namespace — kubectl create namespace construction
  4. Ingress + TLS — Public hostname + HTTPS via cert-manager + Let's Encrypt.
  5. CI/CD — GitHub Actions: build → push → deploy (or Argo CD).
  6. Resource limits — Tune resources in deployment.yaml.
  7. Monitoring — Centralised logs; Prometheus + Grafana.

15. Deploying on a Linux Server

15.1 Get the Project

Option A — Git clone:

bash 
sudo apt update && sudo apt install -y git
git clone https://github.com/ashararsi/Kubernetes.git
cd Kubernetes

15.2 Install Docker (Ubuntu)

bash 
sudo apt update && sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${VERSION_CODENAME:-$VERSION_ID}") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker "$USER"

15.3 Run with Docker Only

bash 
docker build -t construction-node-app:1.0 .
docker run --rm -d --name construction-welcome -p 3000:3000 construction-node-app:1.0

15.4 Kubernetes on Linux

Path A — K3s

bash 
curl -sfL https://get.k3s.io | sh -
sudo mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown "$USER:$USER" ~/.kube/config

bash

alias kubectl='microk8s kubectl'
docker build -t construction-node-app:1.0 .
docker save construction-node-app:1.0 | microk8s ctr image import -
kubectl apply -f deployment.yaml -f service.yaml

Path C — Minikube

bash 
minikube start --driver=docker
eval $(minikube docker-env)
docker build -t construction-node-app:1.0 .
kubectl apply -f deployment.yaml -f service.yaml
minikube service construction-app-svc --url

CI/CD Pipeline (GitHub Actions)

Automate your build and deploy workflow using GitHub Actions. On every push to main, this pipeline builds the Docker image, pushes it to a registry, and rolls out a new deployment.

Trigger
Push to main
Build
docker build
Test
npm test
Push
docker push
Deploy
kubectl apply

Example .github/workflows/deploy.yml:

yaml 
name: Build & Deploy

on:
  push:
    branches: [main]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: Build and push image
        uses: docker/build-push-action@v5
        with:
          push: true
          tags: yourusername/construction-node-app:${{ github.sha }}

      - name: Deploy to Kubernetes
        run: |
          kubectl set image deployment/construction-app \
            web=yourusername/construction-node-app:${{ github.sha }}
          kubectl rollout status deployment/construction-app

Security Hardening

Apply these settings to reduce the attack surface of your deployment before going to production.

Pod Security Context

Add a securityContext to your deployment.yaml container spec to enforce least-privilege execution:

yaml 
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  readOnlyRootFilesystem: true
  allowPrivilegeEscalation: false
  capabilities:
    drop: ["ALL"]

Network Policy — Restrict Ingress

Allow only traffic from the Service to reach your pods:

yaml 
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: construction-app-netpol
spec:
  podSelector:
    matchLabels:
      app: construction-mgmt
  policyTypes:
    - Ingress
  ingress:
    - ports:
        - port: 3000

Advanced Kubernetes Configurations

Horizontal Pod Autoscaler (HPA)

Automatically scale the number of pods when CPU usage exceeds a threshold:

yaml 
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: construction-app-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: construction-app
  minReplicas: 2
  maxReplicas: 8
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 60

Ingress with TLS (NGINX)

Replace NodePort with a proper Ingress resource for HTTPS access with a custom domain:

yaml 
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: construction-app-ingress
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - construction.yourdomain.com
      secretName: construction-app-tls
  rules:
    - host: construction.yourdomain.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: construction-app-svc
                port:
                  number: 80

PodDisruptionBudget

Ensure at least one pod stays running during node drains or cluster upgrades:

yaml 
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: construction-app-pdb
spec:
  minAvailable: 1
  selector:
    matchLabels:
      app: construction-mgmt
